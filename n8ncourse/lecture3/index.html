核心概念：大型語言模型（LLM）

為什麼要先學這個？

你不需要成為 AI 科學家。但對 LLM 有正確認識，會讓你在設計工作流程時少走很多冤枉路——你會知道它能做什麼、不能做什麼，以及為什麼它有時候的行為讓你感到奇怪。

  • 1

    LLM 的本質：一個非常強大的「下一個字預測機器」

    大型語言模型（Large Language Model，LLM）本質上是一個統計程式。它從海量的網路文字資料中學習（這個過程叫做「訓練」），找出語言的模式規律。

    當你輸入一段文字，它做的事情是：根據已學到的模式，預測接下來最可能出現的文字。如果輸入是一個問題，它預測的是答案；如果輸入是「接下來該做什麼」，它預測的是行動。

    它不是在「思考」——它是在做大規模的模式匹配。牢記這一點，對你後續設計工作流程非常重要。
  • 2

    LLM 是「無狀態的」——每次呼叫都是全新開始

    這是很多人沒有意識到的關鍵特性。每當你呼叫一個 LLM（例如 GPT），它對之前發生的任何事情都一無所知。它只接收這一次的輸入，然後給出輸出。

    就像每次打電話，對方都完全失憶，不記得之前任何對話。

    那 ChatGPT 為什麼看起來記得我說過的話？這是靠「技巧」做到的——第五點會詳細說明。
  • 3

    不要把 LLM 當成人類——避免擬人化

    我們很自然地會把 LLM 擬人化——覺得自己在跟它「建立關係」，覺得它有動機、有意圖。這種想法會讓你對它的行為產生錯誤期待，在工作流程出問題時找不到原因。

    實際上，LLM 是一個非常有效的模式匹配統計引擎。它「看起來有智慧」這件事，是大規模訓練的副產品，有人稱之為「突發智慧」——但本質上仍然是統計計算。

    避免擬人化 LLM，會讓你設計出更穩健的工作流程，也更容易在它出現奇怪行為時找到原因。
  • 4

    LLM 能做哪些事？

    雖然本質是統計引擎，但 LLM 能做的事情非常廣泛，因為它在極大規模的資料上訓練過：

    回答問題 生成文字內容 進行對話 決定下一步行動 決定要呼叫哪個工具 預測要執行的指令
    在 n8n 的 AI Agent 節點中，LLM 的核心任務是：根據你的輸入和設定，決定工作流程接下來要執行什麼動作、呼叫什麼工具。
  • 5

    記憶、對話這些「功能」是怎麼做到的？

    我們說 LLM 是無狀態的，但 ChatGPT 看起來能記住你說過的話——這不是矛盾，而是透過巧妙的技術手段做到的。

    例如，所謂的「記憶功能」，實際上是把過去的對話記錄一起塞進這次的輸入中，讓 LLM「看到」之前說過什麼。LLM 本身還是無狀態的——是外部的軟體邏輯在管理這些狀態。

    接下來的課堂會教你怎麼在 n8n 工作流程中實作這些技巧，讓你的 AI Agent 也能「記住」對話內容。
重要區別：模型 vs 產品

很多人分不清楚這兩個東西

「GPT」和「ChatGPT」不是同一個東西。理解這個區別，能讓你更清楚地知道在 n8n 裡你在操作哪個層面的東西。

模型（Model）

GPT — 大型語言模型本體

  • OpenAI 訓練出來的統計引擎本體
  • 接收輸入序列，產生輸出序列
  • 無狀態：每次呼叫都是全新的，不記得之前
  • 不會主動做任何事，需要被呼叫才產生輸出
  • 就是一個功能非常強大的「文字預測函式」
產品（Product）

ChatGPT — 建在模型上的應用軟體

  • OpenAI 建立在 GPT 模型上的軟體產品
  • 加了記憶功能（把對話歷史塞進每次請求）
  • 加了網路搜尋功能
  • 加了圖片生成整合
  • 以上這些都是用一般程式碼寫出來的

這跟我們在 n8n 做的事有什麼關係？

在 Lecture 1，你建的那個工作流程，就是在做一件事：用 n8n 這個軟體，連接 Open Router 上的 LLM 模型，建立一個能夠對話的產品。

你是在做 ChatGPT 做的那件事——只是你自己控制這個產品的行為，而不是被 OpenAI 的產品限制住。Open Router 讓你可以在許多不同的 AI 模型之間切換，這就是它存在的價值。

一個有助於記憶的比喻
🔧

引擎（模型）vs 汽車（產品）

GPT 是引擎：強大，但自己不會跑。ChatGPT 是整台車：有方向盤、儀表板、冷氣，讓你可以真正使用它。你在 n8n 裡做的事，就是自己組裝一台車，選用你想要的引擎，加上你需要的功能——而且比買成品車還要彈性得多。

重點整理：LLM（模型）是無狀態的統計引擎 → ChatGPT（產品）在上面加了記憶、搜尋等功能 → 你在 n8n 建的工作流程，是在做同樣一件事，只是自己掌控所有細節。
核心概念：API

API 到底是什麼？

很多人聽過 API 這個詞，但說不清楚它是什麼。這是因為 API 這個詞本身定義鬆散，被用在很多不同情境。這裡建立一個實用的理解。

API（Application Programming Interface）是一種讓不同軟體程式互相溝通的標準方式。你可以把它想成是軟體世界的「電源插座標準」——因為有統一規格，任何電器都能插進去用，不需要為每個品牌各做一種插座。

多年以前，要連接不同的軟體產品是極大的技術挑戰。現在因為有通用標準，這已經變得容易很多——但連接事物仍然是一項挑戰。這正是 n8n 解決的問題：它把連接不同系統的複雜過程，包裝成幾個設定欄位，讓你不需要自己寫程式碼。

n8n 工作流程呼叫外部 API 的流程
你的 n8n 工作流程 → HTTP 請求 + API 金鑰 → 外部服務（OpenAI、Gmail...）
你的 n8n 工作流程 ← 回傳 JSON 資料 ← 外部服務執行後回應
你會常聽到的 API 相關詞彙
端點（Endpoint） 你呼叫 API 時使用的特定 URL 位址。就像電話分機號碼，每個功能都有自己的端點。
HTTP 請求 API 呼叫通常透過 HTTP 協定進行——和瀏覽網頁使用同樣的技術，只是在呼叫另一個軟體做事。
JSON API 之間交換資料最常用的格式。它是一種程式碼，但也是最低程度的低程式碼——課程後面你會越來越習慣它。
API 金鑰 呼叫 API 時用來證明你身份的「密碼」，讓對方知道是你在發出請求，也知道要把費用計在你的帳戶上。
API 金鑰的完整運作流程
1
你向第三方服務申請帳號例如 Open Router，完成後取得一把專屬於你的 API 金鑰（格式：sk-or-xxxxxxxx）。
2
你在 n8n 填入這把金鑰設定憑證時貼上金鑰。之後每次工作流程呼叫 Open Router，n8n 都會自動帶上這把金鑰。
3
Open Router 收到請求，驗證金鑰確認「是你」在呼叫之後，執行請求（呼叫你選的 AI 模型），然後把結果回傳給你的 n8n 工作流程。
4
費用（如果有的話）計在你的帳戶因為金鑰跟你的帳戶綁定，使用量和費用會被正確歸屬到你的帳號。免費模型則不會有費用產生。
你在 Lecture 1 做的事，就是這整個流程的實際演練：申請 Open Router 帳號 → 取得 API 金鑰 → 填入 n8n 憑證 → 工作流程成功呼叫 AI。你已經完成了一次真實的 API 整合。
