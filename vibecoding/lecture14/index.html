CH 2-7 ✦ 技術方案 ⏱ 約 17 分鐘

爬蟲——看得到就爬得到，
3 招實用技巧

上集講了 API 這座橋樑，但如果網站根本沒開放 API 呢？這集帶你認識爬蟲：怎麼判斷網頁是靜態還是動態、3 招快速判斷法、3 種定位線索，還有不能踩的倫理與法律紅線。

01

爬蟲是什麼？

想像一個情境：你每天早上都要去三個不同網站，抄下競品今天的特價商品，一筆一筆貼進試算表再傳給主管。不難，但很煩、每天都要做，感覺是在浪費生命。

這種重複性的工作，其實有辦法自動完成——這就是爬蟲在做的事。

🕷️ 一句話定義

爬蟲就是讓程式自動造訪指定的網站、找到你要的資料、抓取下來，再整理成你可以直接用的格式（通常是試算表）。

定時自動跑
設定排程，每天上班前自動跑一次，到辦公室時資料早已整理好放在雲端。
需要時手動跑
不想設排程也可以，需要的時候手動執行一次即可，依需求選擇。
競品調查
定期抓取多個網站的產品售價，取代人工比價。
內容整合 / 資料監控
把分散在多頁的公告統一整理，或某個數字一有更新就記錄進試算表。
02

靜態 vs 動態：先搞懂這個

叫 AI 幫你寫爬蟲之前，它很可能會反問：「這個網頁是靜態的還是動態的？」——這個問題真的很重要，它會決定寫程式的難度，也決定要用哪種工具。一般來說靜態網頁幾十分鐘就能搞定，動態網頁可能要花上幾個小時。

靜態網頁
內容在打開之前就已經準備好，每個人看到的都一樣。公司官網介紹頁、活動頁、Landing Page 多屬此類。
動態網頁
內容依使用者或當下資料即時產生。個人化推薦、社群貼文、往下滑一直載入新內容都是典型例子。
💡 真正的重點

現代網站很少是純靜態或純動態，大多是混合式——標題導覽列固定，但留言區、商品列表動態載入。所以判斷重點不是整個網站，而是「你想抓的那筆資料」到底是靜態還是動態。

03

3 招快速判斷：靜態還是動態？

不確定的話，這三招不用寫程式、只要用瀏覽器就能判斷。準確度不同，建議先從第一招開始，不確定再往下一招確認。

1
招式一：檢視網頁原始碼
複製一小段想抓的文字 → 網頁空白處按右鍵選「檢視網頁原始碼」 → Cmd+F（Windows 為 Ctrl+F）搜尋剛複製的文字。找得到＝靜態，找不到＝動態。最快最常用，但不是百分之百準確。
2
招式二：停用 JavaScript
開發人員工具 → 偏好設定 → 偵錯工具區塊 → 勾選「停用 JavaScript」 → 重新整理頁面。資料還在＝靜態，資料破相消失＝動態。更準確，但步驟多一點，檢查完記得取消勾選並重新整理恢復正常。
3
招式三：下載 HTML 檔案
網頁空白處按右鍵選「另存為」，格式選「僅限 HTML」下載後用瀏覽器打開。看得到的內容＝靜態，看不到的＝動態。最直覺的一招。
04

精準定位：3 種方法告訴 AI 要抓哪裡

只給 AI 網址不夠——頁面上有程式碼、Logo、各種無關內容，AI 不知道你要的是哪一塊。給它更精準的「定位」線索，它才能寫出對的程式。

1
原始碼法（靜態首選）
原始碼裡搜尋到目標文字，複製前後包覆它的 HTML 標籤（像 <div>、<span>）連同內容一起貼給 AI。推薦搭配 Google Apps Script，快速簡單又能定時爬取，新手首推組合。
2
元素法（適合動態）
看得到的內容不一定在原始碼裡，但一定在「元素」裡（JS 執行後呈現的完整畫面結構）。開發人員工具 → 點選左上角元素選取圖示 → 點擊目標內容 → 在對應的 HTML 標籤上按右鍵選「複製元素」貼給 AI。適合搭配主控台爬蟲，但只能單次手動執行。
3
網路法
動態資料常是瀏覽器背後向伺服器拉下來的，有點像 API 呼叫。開發人員工具 → 切換「網路」分頁 → 重新整理 → 搜尋關鍵字 → 右鍵選「複製為 cURL 格式」（或 fetch 格式，AI 兩種都看得懂）貼給 AI，請它翻譯成 Google Apps Script。
05

工具選擇決策地圖

把判斷方法跟定位方法整理成一張對照表，四種情境分別適合用什麼工具：

1
靜態資料 → 原始碼法 + Google Apps Script
最輕鬆的情況，可設定定時自動執行，新手首選，強烈推薦。
2
動態資料 → 網路法 + Google Apps Script
找到對應 API 請求翻譯成 GAS，一樣方便好用，但不一定每個網頁都能成功。
3
動態資料、網路法行不通 → 元素法 + 主控台爬蟲
看得到的東西基本上都能抓，但只能單次手動執行，無法定時。
4
前面都失敗 → Python 進階爬蟲
用 Python 操作完整瀏覽器模擬人類操作，幾乎適用任何網站，但難度最高。
⚠️ 心理準備

網站若有嚴謹的反爬蟲機制，不管用哪個方法難度都會大幅提升。原則是：能用簡單的就不要用複雜的，從最輕鬆的方案開始試，真的行不通再往下一個方案。

06

爬蟲倫理與法律提醒

📚 圖書館比喻

把網站想成一間圖書館：進去閱讀資料沒問題，這本來就開放給大家。但如果你短時間把整個圖書館的書全部掃描帶走，館方會阻止你——這就像爬蟲請求太頻繁會被網站封鎖。書可以讀，但不代表可以隨便複製、出版或拿去賣，資料的使用也需要遵守規範。

1
控制請求頻率
每次請求間隔建議 2 到 5 秒。沒設定間隔或低於 1 秒，很容易被封鎖，也會對對方伺服器造成負擔。
2
商業用途要謹慎
把爬下來的資料直接用於商業服務，可能引發版權或法律爭議——知名企業之間就曾因此對簿公堂。
3
台灣的特殊規定
在台灣使用搶票機器人（演唱會、高鐵、台鐵皆同）屬於違法行為，即使是自用也一樣。
✦ 一句話記住

人做起來合理的事情，程式可以做；但變成大量、快速、影響他人的行為，就需要特別小心。
