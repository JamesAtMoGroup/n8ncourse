CH 2-5 ✦ 網頁的外表與內在 ⏱ 約 11 分鐘

前端、後端：
網頁的外表與內在

上集講了平台對應的程式語言，這集深入聊 Web 前端、Web 後端各自怎麼運作，以及它們之間又是怎麼彼此溝通的。

01

Web 前端：下載到你手邊的迷你 App

當你在瀏覽器輸入網址按下 Enter，這不到三秒的時間裡——你的瀏覽器（Chrome / Safari）會去伺服器上把前端的程式下載下來，然後在你的瀏覽器裡執行起來，才變成你眼前看到的畫面。

有沒有覺得這個邏輯很像在手機上下載 App？基本上一樣，只是有一個關鍵差異——Web 前端的下載量極輕量，輕到你幾乎感覺不到。所以你每次打開網頁，其實都是在做「下載→執行」的動作，只是快到沒意識到。

💡 跨裝置的天賦

不管電腦還是手機，只要有瀏覽器就能跑 Web 前端。同一份前端程式可以在各種裝置上跑起來——這就是為什麼網頁比 App 更容易跨裝置，不需要為 iOS 和 Android 各寫一套。

🎨 UI 設計師 vs 前端工程師

你看到的按鈕形狀、顏色配置、畫面排版，通常不是前端工程師決定的——前端工程師的任務是「把設計寫成程式、讓它跑起來」。

實際上是由 UI 設計師（介面設計師）先規劃好設計，交付設計稿給工程師，工程師再依照設計稿把產品做出來。當然有些大神會身兼多職——設計、前端、後端全部自己來。

02

Web 後端：幕後的 24 小時大腦

後端跟前端最大的差別在運作的位置。前端會下載到你的瀏覽器，你看得到、可以直接操作；後端則跑在遠端的伺服器上。

你可以把伺服器想成一台放在資料中心、24 小時不關機的電腦。你平常不會直接接觸到它，但你每一次點擊、每一次操作，其實都在跟它溝通——它一直在幕後幫你處理事情。

📡 統一接收所有客戶端

後端最重要的特質：同時接收來自各種地方的請求——電腦瀏覽器、手機瀏覽器、iOS App、Android App，所有這些客戶端都往同一個後端送請求，後端統一接收、統一處理。

上集提到的「把網路關掉」判斷法：你應該沒辦法看到社群動態、查詢購物訂單、訂票——因為這些功能都需要後端的參與才能完成。

03

前後端如何溝通？

前端跟後端之間的溝通方式其實很直觀——「請求然後回應」的來回流程：

前端發出一個請求 Request → 後端收到後處理 → 把結果回應 Response → 前端把它呈現出來。

📧 範例：打開 Gmail
1
前端我要 Gmail 這個頁面
2
後端回傳前端程式給瀏覽器
3
前端瀏覽器下載 + 執行 → 畫面出現
4
前端點開一封信
5
後端驗權限 → 回傳信件內容
6
前端顯示信件
⚠️ 如果後端出問題？

你可能會遇到幾種情況：信件一直轉圈載入不出來、點開信顯示「無法取得內容」、整個收件匣是空的。某些情況下會看到 503 Server Error 這種錯誤訊息，但更常見的是覺得「網頁卡住了、壞掉了」——基本上都是後端在那個時間點出了問題。

前端 = 你看得到的畫面；後端 = 讓這些畫面能正常運作、拿到資料的前提。

⚡ 加速小撇步：快取 Cache

有沒有遇過，打開一個常去的網站，速度特別快？通常不是因為網速突然變快，而是之前已經造訪過。

瀏覽器會把圖片、CSS、JavaScript 等資源暫存在你的電腦裡。再次打開同一個網站時，有些內容可以直接從本地讀取，不需要每次都重新從後端下載——這個機制就是快取（Cache），讓網站載入速度變得更快。

04

為什麼重要的邏輯一定要放後端？

像登入驗證、付款、權限控制這些跟隱私相關的重要操作，一定要放在後端做，不能在前端做。

還記得前端是什麼嗎？前端是被下載到你瀏覽器上的程式。既然是被「下載」下來的，只要有心人士懂相關技術，就可以在本地端任意修改它。

📁 類比：下載文件

就像你下載了一份文件到電腦——你想怎麼改就怎麼改。前端程式也是一樣的道理，只要下載到手邊，任何人就有機會去修改更動。

💸 情境：電商網站

你在購買商品時，前端會顯示價格和總金額。但如果有人在前端動手腳，把價格從 $1000 改成 $10，然後送出訂單——如果系統只相信前端的資料，就會用 $10 成交。這種情況其實就是「直接影響金流」，問題會非常嚴重。

✓ 正解：後端必須重新驗證

像是價格計算、付款金額、庫存數量、使用者權限這些關鍵邏輯，全部都必須放在後端重新驗證。因為後端的程式跑在伺服器上，一般使用者無法接觸、也無法竄改。

所以你可以這樣理解：前端負責讓你操作系統，後端負責確保這些操作是合法且安全。

✦ 本章重點整理
  • Web 前端 = 迷你 App：被下載到瀏覽器執行；極輕量 + 天生跨裝置（同份程式跑各種裝置）
  • Web 後端 = 24h 大腦：跑在伺服器上，統一接收瀏覽器 / iOS / Android 所有客戶端
  • 溝通 = 請求—回應：前端送需求 → 後端處理 → 回傳；快取讓再訪變快
  • 重要邏輯必須放後端：前端會被竄改；登入 / 付款 / 權限這些一定要後端驗證
  • 後端兩大任務：業務邏輯（規則） + 資料庫（讓資料可被快速找到）
