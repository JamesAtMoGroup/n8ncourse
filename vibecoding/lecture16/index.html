CH 2-9 ✦ 資料儲存 ⏱ 約 10 分鐘

技術方案｜資料庫——
簡易版、專業版，哪個適合我

搞懂在什麼情境要用什麼儲存工具，以及怎麼讓 AI 幫你寫出正確的資料操作程式碼。

01

程式關掉之後，資料去哪了？

在沒有特別保存的情況下，資料只會暫時存在記憶體裡，一旦關掉頁面就被清掉。但訂單、帳號、聊天紀錄之所以不會消失，是因為它們被存到了持久化層（Persistence Layer）——即使程式關掉、伺服器重啟，資料都還在。資料庫就是持久化層當中最核心的角色。

📚 圖書館比喻

找書時不會一本一本翻，而是先查書號再直接找到對應位置。資料庫也一樣——每筆資料有唯一的主鍵（Primary Key），系統透過「索引」直接跳到對應位置，不需要從頭掃描所有資料。有了索引，就算資料量很大，查詢速度也不會慢。

資料庫最基本的單位叫做「資料表（Table）」，可以把它想成 Excel 或 Google Sheets 的分頁：有欄（欄位類型）、有列（一筆資料）。

多張表之間可以透過外鍵（Foreign Key）連接——例如在電商網站裡，每一個商品都有一個專屬的 ID，而「訂單表」裡也會記錄這個商品的 ID，這樣系統就可以知道這筆訂單是買了哪一個商品。這就是關聯式資料庫的核心概念。

02

什麼時候才需要升級？

能不用，先不用。很多工程師一開始就急著搭資料庫，花一個禮拜搞基礎設施，功能一行都還沒寫。驗證想法時，最重要的是快速看到結果——先從 Google Sheets、Notion 或 Airtable 開始就好。

KISS 原則
Keep It Simple & Stupid — 保持簡單，越笨越好

很多工程師嘴上說要遵守 KISS 原則，但做的時候卻搞出超複雜的架構。直接拿試算表當資料庫，才是真正有奉行 KISS 的人。

如果覺得讀取有點慢，先跟 AI 說「幫我加一個快取機制」，大多數延遲問題就解了。真的需要升級的時機：前面所有方式都不夠用，或是同時上線人數超過一百人。

🤔 我現在需要升級嗎？

勾選符合你情況的項目，看看目前適合哪個方案：

✅
試算表就夠用了！
目前完全不需要動到正式資料庫。Google Sheets、Airtable 都是很好的選擇，先把功能做出來最重要。
🔧
先加快取機制試試
先別換資料庫，跟 AI 說「幫我在 Google Sheets 前面加一個快取機制」，大多數延遲問題就能解決，不需要馬上升級。
⚠️
開始評估正式資料庫
快取機制可能不夠用了。建議先試試看 Supabase，它的設定比較簡單，不需要自己管伺服器，是升級的第一步好選擇。
🚀
是時候升級正式資料庫
三個問題都符合，確實需要正式資料庫了。建議從 Supabase（PostgreSQL）入手，或視團隊狀況選擇 MySQL / PostgreSQL。
03

正式資料庫：海豚 vs 大象

確定要升級時，要認識兩個業界公認的標準選項：MySQL（🐬 海豚） 跟 PostgreSQL（🐘 大象）。幾乎所有大型服務——社群媒體、電商平台、新聞網站，一半以上都跑在這兩個上面。工程師聊天時常直接問：「你們用哪一隻？」

比較項目 🐬 MySQL（海豚） 🐘 PostgreSQL（大象）
讀取效能 較快，吞吐量高 近年差距縮小
市占 長年市占第一 近年快速成長
功能完整性 基本功能完整 功能更豐富、彈性更高
適合場景 新聞平台、商品列表等讀取為主的服務 複雜查詢、資料結構不固定的應用
新手入門 需租伺服器自行安裝設定 可透過 Supabase 快速上手
✨ 新手首選：Supabase

試算表不夠用、但還不想自己架伺服器時，推薦 Supabase。它把 PostgreSQL 包裝成很像試算表的介面，可以用滑鼠直接新增資料、修改欄位，也幫你把 API 都準備好了，直接寫程式就能讀寫資料。告訴 AI「我用的是 Supabase」，通常就能直接生成可以跑的程式碼。

04

資料不只有「表格」

存圖片、做語意搜尋、分析大量數據——這些情境，傳統資料表不夠用。以下是三種功能特化的儲存方案。

1
物件儲存（Object Storage）——雲端硬碟，存圖片、PDF、影片、音訊等二進位檔案。路徑對應一個檔案，容量幾乎無限。推薦 Supabase Storage（整合度高）；純靜態圖片可直接放 GitHub。Amazon S3 / Google Cloud Storage 功能完整但計費複雜，新手小心帳單爆炸。
2
向量儲存（Vector Store）——AI 客服、語意搜尋的核心。AI 把文字轉成一串數字（向量），讓你用「語意相似」搜尋，而不是完全符合才找到。例如：搜尋「訂單」也能找到「購買紀錄」「消費明細」。推薦 Supabase 內建；進階需求再考慮 Pinecone。
3
分析型倉儲（Data Warehouse）——超大量統計分析用，像「過去三個月所有訂單的平均金額」。初學階段幾乎不會用到，一般資料庫就夠了，有需求時再來研究。
方案 適用情境 推薦入門工具
試算表 原型驗證、個人工具、內部系統 Google Sheets、Airtable
關聯式資料庫 用戶帳號、訂單、交易紀錄 Supabase（PostgreSQL）
物件儲存 圖片、影片、PDF 等檔案 Supabase Storage / GitHub
向量儲存 語意搜尋、AI 客服、RAG Supabase Vector / Pinecone
分析型倉儲 大規模統計、BI 報表 BigQuery（初學者暫不需要）
💡 Supabase 一站包三種

Supabase 同時提供關聯式資料庫、物件儲存、向量儲存——三種需求一個帳號搞定，API 也是同一套，不需要同時維護多個服務。

05

跟 AI 說清楚你的儲存後端

不管用哪種資料庫，操作都是「存資料」和「讀資料」，但每個平台的寫法完全不同。AI 不知道你用什麼，就沒辦法生成可以直接跑的程式碼。

💬 三個溝通技巧
1
說清楚你用什麼系統——「我用的是 Supabase」「我的資料在 Google Sheets」「我用 MySQL」，讓 AI 選對應的 library。
2
附上官方 API 範例——把 Supabase 官網的 JavaScript Client 查詢範本貼給 AI，說「請依照這個範本幫我寫資料存取層」，AI 就能直接生成可執行的程式碼。
3
不確定時，直接問 AI——「我這個需求用 Google Sheets 可以做到嗎？」「我需要做語意搜尋，應該選哪種儲存後端？」先讓 AI 幫你評估再決定。
